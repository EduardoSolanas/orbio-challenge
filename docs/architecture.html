Northstar Energy support · architecture

Three containers, one shared contract

An nginx container serves the page and is the only public entry point. The gateway runs the conversation and talks to the AI services. The backend-api holds the account and booking data and is reachable only from the gateway. Both services import the same models from shared/.

web/

nginx and the page

Serves index.html, css/ and js/ with no-cache, so a redeploy is picked up. Forwards /api/ and /health to the gateway; every other path is a 404. The page fetches its English text from /api/locales/en at start.

gateway/

The conversation

routes/ take the HTTP calls, conversation/ holds the state machine and validators, providers/ the model adapter, knowledge/ the retrieval, storage.py one JSON file per session. Replies come from templates; the model only extracts facts and answers FAQ questions.

backend_api/

Accounts and bookings

Checks the demo credentials, reports installation status and offers technician windows. Bookings live in a SQLite file; the database refuses a taken window and a second visit for the same account. Windows come from availability.json.

One customer turn

  1. The browser posts the message to /api/sessions/{id}/turns; nginx forwards it.
  2. The gateway locks the session and replays a duplicate request if it has seen the id.
  3. The LLM extracts intent and candidate facts; the validators decide what is accepted.
  4. A policy question retrieves up to two FAQ records and gets a cited, checked answer.
  5. An account action calls the backend-api (verification first); the reply text is a template.
  6. The session is written atomically, then the reply goes back. A failure changes nothing.

Why this shape

  • Private data stays private. The backend-api has no host port and nginx never routes to it.
  • Independent services. Neither imports the other, only shared/, and each image carries just its own code.
  • Swappable models. Any OpenAI-compatible server can fill any role, set in .env.
  • Simple state. JSON sessions as the assignment asks, SQLite for bookings, no server to run.

Run it with docker compose up --build -d --wait --wait-timeout 120 and open http://127.0.0.1:8000. See the README and startup.md for configuration and tests.
